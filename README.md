緋凰·恋語（Hiou Rengo）
====================================================================

这个目录装「用 HMYR 写程序所需要的一切」。判据一句：给写程序的人用的东西
归这里，给跑程序的人用的东西归 D:\Yunooka（湯の岡）。判据失效的时候，
问一句「它是给写程序的人用的，还是给跑程序的人用的」，答案通常就出来了。

出处与定位写在语言仓库的 design/FULLSELF.txt 第七节。那一份是账，这一份是
门口那块牌子 —— 说清这里现在有什么、缺什么、缺的那部分暂时借谁的。


一、现在这里有什么
--------------------------------------------------------------------

    hello.hmyr    第一个程序。它存在的理由是「这里能写程序」这句话要有证据。

两份东西，没有第三份。这不是省略，是一期的形状：先证明这个目录能站人，
再往里搬东西。


二、怎么跑它
--------------------------------------------------------------------

现在还借语言仓库的启动器，因为「跑」这一层属于 湯の岡，还没有 HMYR 写的 VM：

    node "D:\himeyuri\bin\hmyr.mjs" "D:\Hiou Rengo\hello.hmyr"

输出：

    緋凰·恋語 ready: 14
    0

第二行是 main 的返回值 —— 解释那条路会把它一起打出来，那是 REPL 的显示选择。
只要那一行字的话走编译那条：

    node "D:\himeyuri\bin\hmyr.mjs" --compile "D:\Hiou Rengo\hello.hmyr"

输出就只有那一行。两条入口的差别不是随手定的，语言仓库的 bin/hmyr.mjs
文件头写着理由。

这条借据要写在这里，不能装作不存在：一期里緋凰·恋語没有跑自己的能力，
跑是语言仓库那边给的。什么时候还上，取决于 湯の岡 什么时候有 HMYR 写的 VM。

那一行命令里三处引号不是装饰：路径带空格（Hiou Rengo），在 PowerShell 里
不加引号会被拆成两个参数，症状是「cannot open Rengo」这类看不出根因的报错。


三、一期缺什么
--------------------------------------------------------------------

    标准库      仓库里的 self/*.hmyr 是语言的实现，不是给写程序的人的库。
                两者现在互锁：库要用语言的内部形状，改一处会牵动另一处。
    工具链      仓库里的 tools/ 四十三件都围着语言仓库转（打包、清单、发布、
                检查）。它们要变成「给外面的人用的工具」，得先脱开仓库路径。
    验收        这一条最要紧。仓库的 test/ 验的是语言，不是这个 SDK。
                搬进来的东西如果没有自己的验收，就等于没有尺子。

一期的判据只有一条：上面那条命令跑得出那一行字。它现在成立。


四、这个目录的边界
--------------------------------------------------------------------

不从语言仓库复制文件进来。复制会造出两份真相，而两份真相的结局总是
「改了一份，另一份还在看着对」。

要取模块就从发布包取，或者由语言仓库那边给出一个明确的发布物 —— 那是
另一件事，得先有版本号与发布节奏，不是今天这一步。
